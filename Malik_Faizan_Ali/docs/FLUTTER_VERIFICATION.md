## What was checked before that (in the sandbox without Flutter)

| Check | How | What it can catch | What it cannot catch |
|---|---|---|---|
| `tool/dartcheck.py` | script | unbalanced brackets, missing imports, packages missing from pubspec, duplicate top-level class names | type errors, wrong method names |
| `tool/argcheck.py` | script | named arguments passed to project widgets/classes that the constructor does not have | positional mistakes, wrong types |
| `tool/funccheck.py` | script | calls to unknown project helpers (`format*`, `as*`, `show*`, `parse*`, `download*`) and bad named args | helpers with other prefixes |
| Manual review | read against the backend schemas | wrong JSON keys, wrong endpoints/filters, business-rule mismatches | anything visual |

These scripts found and fixed real defects (duplicate `BusyMixin`, a marks field that turned "100" into "1", delete offered for
non-draft exams, a missing `must_change_password` flow, Flutter-version constraints). They are heuristics, **not a compiler**:
expect a handful of ordinary compile/analyzer errors on the first real build (typically a missing import or a type
mismatch). They are quick to fix with the analyzer's messages.

* `lib/src/core/theme.dart` uses `CardThemeData` and `Color.withValues`, so **Flutter >= 3.27 (Dart >= 3.6)** is required.
* `android/` and the web icons are generated by `flutter create`; `mobile_app/tool/patch_android.py` was tested only on a
  hand-made imitation of the generated files.
* Unit/widget tests exist in `shared/siois_ops/test/` (JSON/format helpers, model parsing against real API shapes, a few
  widget smoke tests). **They have not been run.**
* Push notifications (FCM) are optional, need your own Firebase project, and are untested (`mobile_app/PUSH_SETUP.md`).

## First real build - do this in order (about 15-30 minutes)

```bash
# 0. one-time: Flutter >= 3.27 installed, backend running (see SETUP_GUIDE)
cd shared/siois_ops
bash tool/verify.sh            # runs the 3 scripts, then pub get / analyze / test for the package and both apps
```
Fix whatever `flutter analyze` reports (start from the first error; many later ones disappear). Then:

```bash
cd ../../web_app

flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000 --dart-define=DEMO_PASSWORD=School@12345
```

## Known behaviour that is intentional

Students do not see fees (parents/admin only). Attendance % = (present+late)/(present+late+absent); leave days are excluded.
Teachers may edit only the last 7 days of attendance. Sundays and holiday events block marking.
